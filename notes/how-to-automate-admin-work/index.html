How to automate admin work (a method, not a tool list)

Most "automate your admin" advice sells you software first. This does it the other way round: sort the work, test each task against three questions, then build the smallest thing that clears the biggest pile.

Johan Iskandar · 27 July 2026

To automate admin work in an Australian SMB, don't start with a tool — start by sorting the work into what a system can own and what still needs a person. Most admin isn't one job; it's dozens of small tasks glued together, and only some of them are ready to hand off. This is the triage method we run before quoting anything: three questions per task, then a ranked shortlist.

Buying software first is the common mistake. You end up with a subscription that automates the easy 20% and leaves the 80% that actually eats the day. The order that works is the reverse: name the tasks, test each one, then pick the smallest build that clears the biggest pile.

Step 1 — List the tasks, not the roles

Write down the repeatable admin your week actually contains: replying to the same enquiry, chasing the same missing info, re-typing form data into your CRM, booking and rebooking, sending the same three follow-ups. Be granular. "Manage the inbox" is a role; "send the standard quote-follow-up on day 2 and day 5" is a task — and tasks are what get automated, not roles.

Step 2 — Run each task through three questions

This is the whole method. A task is a candidate for automation only if the answer to all three is yes:

  • Is the input readable? Does the work arrive as text, a form, a call, an email — something a system can actually take in?
  • Are the rules statable? Could you write the decision down as steps a new hire would follow without asking you?
  • Is the action loggable? Can every step it takes be recorded so you can check it later?

Those three questions are the same test that defines what an AI agent actually is. If a task fails one — the input is a hallway conversation, the rules live only in your head, the action can't be traced — it stays with a human for now. No shame in that; forcing judgment-heavy work onto a system is how automation projects fail.

Step 3 — Rank by pain × volume, automate the top one

For every task that passed, multiply how much it hurts by how often it happens. A painful task you do twice a month isn't the place to start; a mildly annoying one you do forty times a day is. The winner is usually obvious once it's on paper — and it's almost never the task people expected. Start there, prove it, then move down the list. One workflow owned completely beats five half-automated.

What this looks like in practice

A trades business lists twelve admin tasks. Nine pass the three questions; the top of the ranked list is "answer and triage every missed call," because missed calls are both high-volume and directly lost revenue. That becomes the first build — not a generic "office automation platform." The remaining eight tasks get sequenced behind it, each priced only when the one before it is proven under supervision.

Questions people actually ask

List your repeatable admin as individual tasks (not roles), run each through three questions — is the input readable, are the rules statable, is the action loggable — then rank the ones that pass by pain times volume and automate the top one first.

The task with the highest pain-times-volume score that also passes all three readiness questions. It's usually a high-frequency, rule-bound task like enquiry replies, missed-call triage, or form-to-CRM data entry — rarely the task people first assume.

Anything where the input isn't readable by a system, the rules live only in your head, or the action can't be logged and checked. Judgment-heavy, varied, or relationship-driven work stays with a person until it can be clearly defined.

Not necessarily, and not first. Start by triaging the work; sometimes a checklist or a settings change fixes it cheaper than any tool. Only build or buy once you know which specific task pays back and how.

An owned agent is a fixed price quoted in writing after scoping, then roughly A$50–300 a month to run for most single-workflow agents (market figures — your spec carries your number). The point of triage is to spend that on the workflow with the fastest payback.

It depends on the workflow, but a single well-scoped task — one readable input, statable rules, loggable actions — is a small build. The triage step is fast; the discipline is resisting the urge to automate ten things at once instead of proving one.
